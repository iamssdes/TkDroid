# Changelog

## v4.1.2
- **`pockettk check` shows warnings only,** as its help says (desktop and Android). It used to print the whole generated Java file and, on the desktop, dropped the warnings. Now it prints the transpiler's `warning:` / `note:` lines and a summary (`no warnings`, `1 warning`, `2 warnings`). `check -v` (or `--java`) also prints the generated Java. The window's `check` was already like this.
- The generated Java no longer says "Generated by ApkApple" in its header comment (it says PocketTk).

## v4.1.1: wider tkinter support
- **Canvas** grew: arcs, filled and smooth polygons, smooth and dashed lines, arrows, text with anchor / bold / wrapping / several lines, hidden items, and the methods `moveto`, `scale`, `itemcget`, `type`, `gettags`, `bbox`, `find_closest/overlapping/enclosed/above/below/withtag`, `addtag_*`, `dtag`, `tag_raise/lower`, and `tag_bind` (tap, release, drag on an item; `"current"`). **Fix:** canvas drawing was scaled by a rounded density (3 instead of 2.625 on many phones), so drawings came out too big for their canvas; they now match the canvas size.
- **Treeview** and **LabeledScale** are real widgets (they were placeholders).
- **Images**: `PhotoImage` (file, base64 data, size, zoom, subsample, copy, put, get), `image=` / `compound=` on Label and Button, and `Canvas.create_image`. The PC preview got the matching Android pieces (Bitmap, BitmapFactory, BitmapDrawable, compound drawables on text views).

## v4.1.0
- **The PocketTk window for macOS, Windows and Linux (no system terminal needed).** It is terminal-style: a prompt with history and Tab completion (commands, options, app ids, paths), our own commands (`pick`, `use`, `build`, `check`, `preview`, `install`, `devices`, `update`, `apps`, `doctor`, `setup`, `cd`, `ls`, `reveal`, `outdir`, `theme`, `help`), live build output, Ctrl+C to cancel, drag a `.py` onto the window, the Android SDK licence and keystore password asked on the prompt line, four colour themes. APK or Google Play `.aab`. No local web server or network port (pywebview's own bridge). `pockettk gui [file] [--pick]` opens it. `webui/`, `pockettk_gui.py`.
- **Packages:** macOS `.dmg` (Apple Silicon, Intel), Windows installer (per-user, no admin rights) and portable `.zip`, Linux `.AppImage` (one file, double-click; needs FUSE) and `.tar.gz` with `./install.sh`. Each carries its own Python and pywebview (Linux: Qt WebEngine from pip wheels). `packaging/macos/`, `packaging/windows/`, `packaging/linux/`, built by `.github/workflows/apps.yml` on a `v*` tag (a tag with a `-`, like `v4.1.0-rc1`, makes a pre-release).
- **The app installs its own dependencies** on first start: a JDK (Eclipse Temurin), Google's Android build tools (you accept the SDK licence on the prompt) and bundletool, all into `~/.pockettk`. No administrator password. `pockettk_deps.py`. A JDK PocketTk downloaded itself is found by every command.
- The Windows app runs without a console: output goes to `~/.pockettk/gui.log`, build tools do not flash console windows.
- **New logo** (a phone with "Tk" peeking out of a pocket): `packaging/logo.svg`; the app icons are drawn from it. **Flashing the module prints the logo** as plain ASCII (no colour, no box-drawing characters: the KernelSU flash screen does not render them reliably).
- **macOS bundle id is `com.ssdes.pockettk`.** Old `tkdroid.palalgon.*` apps are still recognized and moved by `update`.
- **Android has no window.** `pockettk gui` and `pockettk make-gui` just say so; use the commands. (Flashing the module, or the install step, removes leftovers of earlier test builds of an Android window.)
- **New directive `#use: termux-connect` and `import termux`** for any app: `termux.state()`, `termux.ask()`, `termux.run(args, callback)`. It runs a command in Termux through Termux's `RUN_COMMAND` intent and returns exit code, stdout and stderr; the directive adds the `com.termux.permission.RUN_COMMAND` permission, a package query and a result receiver to the manifest, and `import termux` without the directive is an error. Needs `allow-external-apps = true` in Termux's `termux.properties` (add it yourself, then `termux-reload-settings`).
- Tests: `tests/test_deps.py`, `test_gui.py`, `test_packaging.py`, `test_termux_connect.py`, `test_terminal_page.py` (real page in headless Chromium when Playwright is installed), `test_core.js`, `test_shell.js`.
- **Not tested on real systems yet:** the window on a real Mac, Windows or Linux desktop, the CI builds, the installer and AppImage, the first-run downloads, and `#use: termux-connect` on a phone were only tested here with stand-ins.

Fixes found by the first GitHub Actions runs (included in this release):
- **Windows build fix:** the Windows job of the Desktop apps workflow stopped at "self-test failed", which also stopped the release. The build script started the window with `python -I`, and isolated mode leaves the script's own folder off `sys.path`, so `import pockettk` crashed before the check ran (reproduced). The window now puts its own folder on the path itself, so it starts under `-I` too, and the build script's self-test starts it the way `PocketTk.cmd` and the installer shortcut do (same environment, no `-I`). The error now says the exit code.
- **Linux build fix:** the Qt WebEngine check failed on the arm64 runner with `libopus.so.0: cannot open shared object file`, the same kind of failure `libminizip` was in v4.1.1: the list of system libraries was copied by hand into four places, and each CI run found the next one that had fallen behind. There is now **one list, `packaging/linux/system-libs.txt`** (with `libopus0` added). Both workflows install it, the build script writes it into the `READ ME FIRST.txt` inside the `.tar.gz`, and the hint printed when the check fails is built from the `ldd` output: it names the package for each library that is actually missing, then the whole list. A missing library that is not in the table is printed by name.
- Tests (`tests/test_packaging.py`, class `CiFailuresStayFixed`): the window starts under `-I`; the Windows self-test does not use `-I`; the library list exists once and both workflows and the README use it; the hint turns `libopus.so.0 => not found` into `sudo apt install libopus0`. Each was checked by putting the bug back and watching the test fail.
- Not run here: the GitHub Actions jobs themselves (Qt WebEngine, the Windows build, Inno Setup). The Linux fix follows from the log (`libopus.so.0` was the only library `ldd` reported missing); the Windows fix was reproduced and checked with a stand-in `pywebview`.
- **Linux build fix:** the Qt WebEngine check failed on the arm64 runner with `libminizip.so.1: cannot open shared object file`. `libminizip1t64` is now installed in both workflows, listed in the Linux READ ME FIRST, and named in the build script's hint.
- **Desktop test workflow (`.github/workflows/desktop-test.yml`).** Run it by hand from GitHub (Actions > Desktop test > Run workflow; the phone's browser works). On Windows, macOS and Linux it runs (1) the whole test suite, (2) the real PocketTk window (`POCKETTK_GUI_SMOKE`: the page and the Python bridge must answer, with a screenshot attached) and (3) the first-run setup (JDK + Android SDK) followed by building a real APK and a Google Play bundle (`tests/ci_e2e.py`). Results show as ticks and crosses, a table on the run's summary page, and downloadable artifacts. Not run anywhere yet.
- **CI fixes (from the first run of the Desktop apps workflow):** the Linux aarch64 build failed at "Build the app and the .tar.gz", which also stopped the release. The Linux build now installs Qt with binary wheels only, tries PyQt6 and falls back to PySide6 where PyQt6 has no WebEngine wheels (it records which one in `qt-api` for the launchers and the AppImage), checks it through `qtpy` (what pywebview uses) and, if Qt does not start, prints the system libraries that are missing. The workflow installs every library Qt WebEngine needs (the arm64 runner has fewer preinstalled), and the aarch64 job is `experimental` so it cannot block the other files of a release. macOS runners are now `macos-15` (Apple Silicon) and `macos-15-intel` (Intel); `macos-13` no longer exists.
- **Windows build fix (dexing):** `The command line is too long.` stopped every APK and AAB build on Windows, because `d8` is a `.bat` file there and was given every runtime `.class` file on one command line. When the list is long, `pockettk.py` now gives `d8` one temporary jar instead.
- **CI test fixes:** the JDK-lookup test compares real paths (macOS `/private/var`, Windows `RUNNER~1`); two tests that run Linux shell scripts are skipped on Windows (the Linux and macOS jobs run them); `.gitattributes` keeps shell scripts LF on Windows checkouts.

## v4.0.0
- **Renamed to PocketTk** (was TkDroid, before that ApkApple). Command `pockettk`; `tkdroid`, `apkapple` and `apple` still work but are deprecated and print a warning.
- New app packages are `pockettk.ssdes.<id>`. `update` / `update-all` move apps from `tkdroid.ssdes.*` and older to the new package, copying their data (needs root; without root the old app is kept).
- Flashing the module moves `~/.tkdroid`, `/data/adb/tkdroid` and the TkDroid folders on the SD card to their PocketTk names, signing key included.
- **Runs without root** in Termux: installs through Android's installer, or silently with adb. `termux_setup.sh` installs the tools.
- **Windows, Linux and macOS**: `pockettk.py` (Python 3.8+, JDK) builds, installs over adb, and has `--aab` for Google Play bundles.
- **PC preview window**: run the app's real code in a phone-shaped window with selectable Height, Width, density and CPU strength (approximate, not Android).
- **iOS, macOS only, experimental**: `--ipa` translates a core subset of tkinter to Swift and builds an .ipa; `--simulator` runs it in the iOS Simulator. Never compiled on a real Mac yet.
- About page updated.
